# 产品需求（MVP）

## 1. 产品目标

将抖音店铺、快手店铺、视频号/微信小店的数据自动汇总到一个经营后台，帮助商家每天快速判断：

- 哪个平台卖得最好
- 哪个店铺增长最快
- 哪些商品卖得最好
- 同一商品在哪个平台表现最好
- 哪些商品退款异常
- 哪些商品正在起量或下滑

不要求商家每天人工导出 Excel。

## 2. MVP 页面

### 2.1 经营总览
支持时间范围：今日、昨日、近 7 天、近 30 天、自定义。

核心卡片：
- GMV / 支付销售额
- 净销售额
- 支付订单数
- 销售件数
- 客单价
- 退款金额
- 退款率

图表：
- 每日销售额趋势
- 每日订单量趋势
- 各平台销售额占比

### 2.2 店铺对比
按店铺和平台展示：
- 销售额
- 订单数
- 销量
- 客单价
- 退款金额
- 退款率
- 净销售额
- 较上一周期变化

支持排序。

### 2.3 商品排行榜
字段：
- 统一商品名称
- 统一货号
- 销量
- 销售额
- 净销售额
- 退款率
- 平台贡献占比
- 7 日趋势
- 30 日趋势

支持按销量、销售额、净销售额、退款率排序。

### 2.4 单品分析
查看一个统一商品在抖音、快手、视频号/微信小店的分别表现。

包含：
- 各平台销量
- 各平台销售额
- 各平台退款率
- 各平台客单价
- 趋势曲线
- SKU 维度拆分

### 2.5 商品映射
系统需要建立“统一商品”与“平台商品”的映射。

优先匹配：
1. 商家货号 / merchant SKU code
2. SKU code
3. 人工确认映射

禁止只依靠商品标题做最终自动合并。

### 2.6 同步状态
展示：
- 平台连接状态
- 最后成功同步时间
- 本次同步时间范围
- 同步数据条数
- 是否失败
- 错误摘要
- 重试按钮（后续）

## 3. 指标口径

### 支付销售额
按支付成功订单商品实付金额汇总。

### 净销售额
`支付销售额 - 已确认退款金额`

### 支付订单数
去重后的支付成功主订单数。

### 销售件数
支付成功商品数量之和，退款口径单独展示，不直接从销量中扣除，除非页面明确选择“净销量”。

### 客单价
`支付销售额 / 支付订单数`

### 退款率（金额）
`退款金额 / 支付销售额`

## 4. 自动化要求

- 每天自动同步至少一次
- 推荐增量同步每 30~60 分钟一次（平台限流允许时）
- 每日凌晨做上一自然日补偿同步
- 失败自动重试
- 支持补拉指定时间范围
- 同一数据重复同步必须幂等

## 5. 非功能要求

- 中文界面优先
- 桌面端优先，兼容手机查看
- 页面首次加载应尽量在 3 秒内展示聚合数据
- 关键聚合指标应预计算或缓存
- 所有平台敏感凭证必须加密存储
- 日志中不得输出完整 Access Token / Secret
